# 동작 상세 (개발자용)

> 사용자용 소개는 [README](../README.md). 이 문서는 자동 판단 규칙, 고글 연동, HUD·OSD 합성, 렌더 안정 장치의 세부 동작을 적어 둔 것입니다.

## 개요

1. **병합** — 4GB(7:40) 분할 영상과 이어 찍은 클립을 비행 단위로 자동으로 묶고, 재압축 없이 이어붙인 뒤 프레임 수로 검증
2. **오버레이** — 영상 안의 비행 데이터(djmd)로 자세계·방위계·미니맵·속도/고도 HUD 합성, 고글 녹화를 자동 동기화해 OSD 띠 합성
3. 두 단계는 "병합하고 오버레이 만들기" 한 번으로 이어서 실행 (각각 따로도 가능). 연결된 고글 녹화가 여럿이면 같은 방식으로 무손실 병합 + 프레임 검증
4. YouTube 업로드는 설정에서 켠 경우에만 보이는 옵션

## 폴더 구조 (앱이 자동 생성)

| 위치 | 의미 |
|---|---|
| `<폴더>/` | 병합 대기 — SD 카드의 `DJI_*.MP4/.LRF/.SRT` 를 여기에 복사 |
| `2_ready/` | 완성된 영상 (`*_merged.MP4`, 단일 클립, `*_hud.MP4` 오버레이, `*_goggles.MP4` 고글 녹화 병합본) + `*.telemetry.json` |
| `3_uploaded/` | YouTube 업로드 후 (업로드 기능 사용 시) |
| `_sources/` | 병합에 쓰인 원본 (지우지 않음) |
| `_excluded/` | 제외 클립 정리 시 |
| `goggles/` | 고글 녹화 파일 ("고글 영상 추가" 또는 직접 복사) |
| `dji_state.json` | 기록·수동 선택·비행별 오버레이 설정·고글 연결 |

## 자동 판단

- 5초 미만 클립 제외 / 직전 영상과 간격 3초 이하일 때만 이어붙임 후보
- 직전 영상 ≥455초 + 간격 ≤1.5초 = DJI 자동분할 → 항상 병합
- 그 외: 앞 영상 마지막 프레임 vs 다음 첫 프레임 연속성 점수 ≤0.4 → 같은 장면으로 병합
- 비행 카드 아래 단계 표시: 드론 병합 · 고글(없음/찾음/연결/병합) · HUD · 업로드(YouTube 켰을 때). 비행 화면 위쪽 단계에도 고글이 있으면 "고글" 단계가 붙음
- 비행을 열면 큰 플레이어 + 타임라인(클립·이음매·고글 구간). 병합 전에도 클립을 이어 재생해 결과를 미리 확인, 이음매를 누르면 앞뒤 프레임 비교 후 분리/제외 가능

## 고글 연동 (DJI Goggles 3 실측 기준)

- 폴더를 열면 고글 녹화 후보가 있는 **모든 비행을 차례로 자동 맞춤** (비행·후보 조합마다 한 번, 진행 카드에서 중단 가능)
- 첫 화면에서 **드론 영상 폴더(필수, 작업 폴더)** 와 **고글 녹화 폴더(선택)** 를 정함. 고글 폴더는 복사 없이 읽기만 하고 3단계 아래(DCIM/100MEDIA)까지 찾음. 둘 다 기억해 두었다가 다음에 그대로 염. SD 카드가 빠져 있으면 사이드바에 "다시 연결" 표시
- "SD 카드에서 복사": 고글 SD 카드(또는 DCIM) 폴더를 고르면 비행과 촬영 시각이 겹치는 녹화만 골라 goggles/ 로 복사 (같은 파일은 건너뜀, 이름만 같은 다른 파일은 _2 로 저장, 중단 시 반쪽 파일 삭제). goggles/ 나 폴더 맨 위에 직접 넣어도 인식
- 고글은 드론 녹화 버튼과 함께 켜지고 꺼지며 7:40 분할이 없다 → 드론 클립마다 겹치는 고글 파일을 자동 연결
  (3클립 비행 = 고글 3개, 자동분할 비행 = 고글 1개)
- 시간 맞춤: 촬영 시각으로 대략 맞춘 뒤 움직임 + 화면 내용 상관이 최대인 지연을 찾음.
  실측: 고글이 드론 첫 프레임보다 약 0.6초 먼저 시작 (일치도 0.68~0.88). 프레임 단위 수동 조정 가능
- OSD 합성: 기본 = 하단 13% 한 줄 + 검은 배경 지우기 (아래 "HUD · 고글 OSD" 참고)
- 고글 녹화에는 메뉴·경고창도 찍힘 → 고글 화면이 드론 화면과 0.4초 이상 다르면 그동안 OSD 를 붙이지 않음
  (실측: 10/11 비행의 충돌 경고 0~100초 구간 자동 숨김, 이후 자동 표시)

## HUD · 고글 OSD (프로젝트의 HUD 탭 / 고글 탭)
- 탭 구성: **병합 · HUD · 고글 · YouTube**. HUD 탭을 열면 플레이어 위에서 바로 위젯 편집, 고글 탭을 열면 OSD 가져올 영역 편집.
  따로 "편집 모드"나 저장 버튼 없음 — 손을 멈추면(0.3초) 저장, **Ctrl+Z 되돌리기 / Ctrl+Shift+Z 다시**, "초기화"
- 각 탭 맨 위 스위치 = 이 비행에 HUD / 고글 OSD 를 넣을지 (비행별). 배치·테마는 모든 비행 공통
- HUD = **위젯** 목록. 위젯 12종: 자세계, 방위계(원형), 방위 테이프, 수평선·피치 사다리, 미니맵, 속도·고도·상승률 줄, 속도, 고도, 상승률, 이륙 지점 거리, 비행 시간, GPS 좌표.
  화면 위젯 목록과 플레이어 선택이 연동, 추가/빼기(Delete 키)·이동·크기 조절, 위젯마다 다른 테마 선택("테마 따름"이 기본)
- **테마**(15종) = 모양만 바꿈, 위젯 위치는 유지. **배치 템플릿**(8종) = 위젯 구성을 통째로 바꿈. "초기화" = 지금 테마의 추천 템플릿
- 예전에 저장한 배치(자세계·방위계·미니맵·수치 상자)는 위젯 4개로 자동 변환
- **스냅** (`src/snap.ts`, Alt 로 일시 해제): 화면 가장자리·가운데·안전 여백, 다른 위젯의 가장자리·가운데, 일정 간격(GAP)을 둔 옆자리,
  **원끼리 맞닿기**(대각선 포함, 중심 거리 = 반지름 합 또는 + 간격), 크기 조절 시 **같은 종류 위젯과 같은 크기**. 맞춰진 상대 위젯은 분홍 테두리, "맞닿음"/"같은 크기" 표시
- 화살표 1px · Shift 10px, Esc 선택 해제
- 플레이어는 항상 원본 위에 HUD·고글 OSD 를 실시간으로 겹쳐 그림. 구운 영상은 "완성 영상 보기"
- 숫자: [레이블][고정 폭·오른쪽 정렬 값][단위] 칸 분리 → 값이 바뀌어도 위치 고정. 글꼴 모노/7-세그먼트/스타일 글꼴, 크기·색 선택.
  7-세그먼트는 숫자 뒤 배경 **투명 / 검은 판** 선택 (판 너비는 가장 긴 값 기준으로 고정)
- 고글 OSD: 고글 화면 전체를 반투명하게 겹쳐 보여 주고, 사각/원형 영역 그리기·가장자리 블러·검은 배경 지우기(밝기 키)
- 고글 녹화 화면 배율은 **파일마다** 자동 감지 (키프레임 24장 다수결, 고글 카드에서 변경 가능). 같은 장면들로 "고정 OSD 통계"도 만듦
  (1920×1080 누적. 늘 흰 자리 = 고정 OSD, 가끔 흰 자리 = 숫자 자리, 글자 구멍이 완전히 둘러싸인 흰 덩어리 = 모드 표시 M/S/N →
  평행사변형 모양 그대로 상자는 흰색, 글자는 검게. 모드가 바뀌어도 프레임마다 판단)
  - 축소 화면(권장): 검은 여백만 지움 (꽉 찬 기호 안 검은 글자는 유지)
  - 전체 화면 100%: 고정 OSD 는 통계로, 숫자는 "흰/빨강·주황 + 바로 옆 그림자"로(숫자 자리 안에서만), 빨강·주황(경고 상자·배터리·GPS 아이콘)은 오른쪽 아래 인디케이터 줄(가로 50% 오른쪽, 세로 78% 아래)에서만 인식.
    그림자는 새로 그림. 실측(DJI_0045 추락 직후 꽃밭 장면)에서 OSD 주변에 작은 조각이 조금 남음

## 실행 / 배포

```sh
pnpm install
pnpm dev        # http://localhost:5173
pnpm test       # 병합기·선별·텔레메트리·동기화 테스트 (상위 폴더 실제 파일 사용)
pnpm deploy     # Cloudflare Pages (wrangler login 필요)
```

`.env` (선택, 앱 설정 화면에서도 입력 가능): `VITE_GOOGLE_MAPS_API_KEY` (Map Tiles API, 한국 위성은 z15 까지),
`VITE_GOOGLE_CLIENT_ID` (웹 애플리케이션 OAuth 클라이언트, 업로드용). VITE_ 값은 번들에 포함되므로 리퍼러 제한 필수.

## 비행기록 요약 (선택)
- 기체·고글에서 꺼낸 `FlightRecords` 폴더(DJIFlightRecord_*.txt)를 사이드바 "비행기록 폴더"로 정하거나, 드론 폴더 안 `FlightRecords/`·고글 폴더에 두면 자동으로 찾음
- `src/flightlog.ts`: 파일 앞부분 요약만 읽음 (v6~v14, v13+ 는 XOR 된 첫 보조 블록). 시작 시각·비행 시간·거리·최고 고도/속도·영상 녹화 시간·기체명(시리얼은 끝 4자리만)
- 영상 시간과 가장 많이 겹치는 기록을 짝지음 (겹침 없으면 2분 안에서 가장 가까운 것). 카드에 "비행기록 12:49" 표시, 병합 탭에 요약·비행 중 영상 구간 막대
- 스틱·자세·배터리 같은 본문은 v13+ 에서 AES 암호화 → DJI 앱 키(+ 키 요청 중계)가 있어야 읽을 수 있음. 지금은 읽지 않음

## 일괄 처리 · 안정 장치
- 라이브러리 상단 **"모두 처리 (n)"**: 병합 대기 비행 병합 + HUD 영상이 없는 비행의 HUD 만들기를 시간순으로 차례로. 하나가 실패해도 다음 비행은 계속, 중단하면 거기서 멈춤.
  HUD·고글 OSD 를 끈 비행은 병합만, 비행 데이터가 없는 비행은 병합만 하고 알림
- 화면 일부가 오류로 그려지지 않으면 그 부분만 "다시 시도 / 돌아가기 / 오류 내용 복사" 안내 (앱 전체가 하얗게 죽지 않음)
- 폴더를 열 때 지난번에 남은 `*.part` 임시 파일 정리
- 앱 아이콘·매니페스트: Chrome/Edge 에서 "앱 설치"로 따로 창을 띄워 쓸 수 있음

## 오버레이 렌더 안정성 (`src/render.ts`)
- 임시 파일(`*_hud.MP4.part`)에 만들고 프레임 수 검증 후 교체 → 실패·중단해도 기존 HUD 영상은 그대로
- 성공·실패·중단 모두 디코더/인코더·남은 프레임을 닫음 (하드웨어 디코더 슬롯·GPU 메모리 누수 방지)
- 백그라운드 탭에서도 느려지지 않게 setTimeout 대신 MessageChannel 양보 + 코덱 `dequeue` 이벤트로 대기
- 작업 중 화면 꺼짐 방지(Wake Lock), 페이지 닫기 전 경고
- 인코더: 해상도×fps 로 H.264 레벨 선택(4K60 = 5.2), 비트레이트 20~120 Mbps 비례, 하드웨어→소프트웨어 순으로 지원 설정 탐색. 디코더도 하드웨어→소프트웨어
- 디스크 쓰기가 밀리면(96MB 이상) 인코딩을 기다림, 쓰기 오류는 즉시 중단
- 원본의 깨진 프레임: 다음 키프레임부터 디코더 재시작(최대 5번), 건너뛴 프레임 수 알림. 고글 파일이 깨지면 그 구간만 OSD 없이 계속
- 디코더·인코더가 30초(전체 1분) 응답 없으면 멈춘 것으로 보고 오류
- 디스크 부족·권한·파일 사라짐 오류는 알아볼 수 있는 문장으로

## 개발용 페이지

`pnpm dev` 상태에서 실제 영상 폴더를 `?dir=/절대/경로` 로 넘겨 씁니다 (한 번 주면 브라우저가 기억). 영상 폴더가 `web/` 의 상위 폴더가 아니면 `DJI_TEST_DIR=/절대/경로 pnpm dev` 로 띄워야 Vite 가 파일을 읽을 수 있습니다.

- `/opfs-setup.html` + `/?opfs` — 실제 파일을 브라우저 내부 저장소(OPFS)에 복사해 폴더 선택 없이 헤드리스 검증
- `/hud-test.html`, `/sync-test.html`, `/sync-real.html`, `/browser-test.html` — HUD 합성·고글 동기화·병합 단독 검증
- `/docs/readme-shots.html` — README 의 HUD 예시 그림 생성 (가짜 비행 데이터 + 실제 `drawHud`)
