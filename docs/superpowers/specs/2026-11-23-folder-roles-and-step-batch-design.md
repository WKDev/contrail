# 폴더 역할 분리 + 단계별 일괄 처리 설계

작성: 2026-11-23 · 상태: 승인 대기

## 왜

- 드론 비행 영상 아카이브(`~/Desktop/Avata2`)를 Contrail 제품 코드와 분리했다. 아카이브는 원본/병합본을 폴더로 나눠 보관한다:
  `aircraft_raw/`(드론 원본), `google_raw/`(고글 원본), `aircraft_merged/`(드론 병합본 13개), `dji_state.json`.
- 지금 앱은 "고른 폴더 = 원본 + 그 안의 `2_ready/`" 구조를 전제로 하고, 병합하면 원본을 `_sources/`·`2_ready/` 로 **옮긴다**.
  원본이 루트에 남아 있으면 "병합 대기"로 본다 → Avata2 를 열면 원본 101개가 전부 대기로 보이고 병합본을 못 알아본다.
- 사용자는 작업을 단계로 나눠 **단계마다 일괄 실행**하고 싶다: ① 드론 병합 ② 고글 병합 ③ HUD. 지금은 비행마다 세 단계를 한꺼번에 하는 "모두 처리" 하나뿐.
- 구글 지도가 안 뜨는 원인은 키의 리퍼러 제한(`localhost` 미허용, 403)인데 앱이 오류를 삼켜서 원인이 안 보였다.

## 목표

1. 폴더를 **역할별로** 지정: 드론 원본, 고글 원본, ① 드론 병합본, ② 고글 병합본, ③ HUD 영상, 비행기록(선택). 상태 파일은 프로젝트 폴더.
2. 원본 폴더는 **읽기만** 한다. 어떤 작업도 원본을 옮기거나 지우지 않는다.
3. 프로젝트 폴더 하나를 고르면 하위 폴더 이름으로 역할을 자동으로 채우고, 칸마다 바꿀 수 있다.
4. 첫 화면은 **흐름도형**(사용자 선택, 목업 B): 원본 → 병합 → 합성 흐름 위에 폴더 칸이 놓인다.
5. 라이브러리 위에 같은 흐름의 **단계 줄**: 단계마다 대상 수 + 실행 버튼, 그리고 "전부 순서대로".
6. Avata2 의 기존 결과(병합본 13개, 고글 연결, 레이아웃, 수동 선택)가 그대로 "완료"로 보인다.
7. 지도 타일 실패를 화면에 알린다.

## 비목표

- 서버·클라우드 저장, 여러 프로젝트 동시 열기.
- HUD 렌더러·병합기·고글 동기화 알고리즘 변경 (호출 순서만 바꾼다).
- Google Cloud 키 설정 변경 (사용자가 콘솔에서 `http://localhost:5173/*` 추가).

## 실패로 보는 것 (반대 목표)

- 원본 폴더의 파일이 하나라도 옮겨지거나 지워짐.
- Avata2 를 열었더니 이미 병합된 비행을 다시 병합하려 함 (26GB 중복).
- 예전 구조 폴더(루트 + `2_ready/`)를 쓰던 사람이 열었을 때 결과물이 사라진 것처럼 보임.

## 접근 방법 (검토한 것)

| 안 | 내용 | 결과 |
|---|---|---|
| A | Avata2 를 앱 구조(`aircraft_raw/2_ready`)에 맞게 재배치, 코드 변경 없음 | 사용자가 거절 — 아카이브 구조를 앱에 맞추지 않음 |
| B-1 | 프로젝트 폴더 하나 + 하위 폴더 이름 규칙으로 역할 자동 인식 | **채택(B-2 와 결합)** |
| B-2 | 역할마다 폴더를 따로 고름 | **채택(B-1 과 결합)** — 자동 채움 후 칸마다 바꾸기 |
| — | `2_ready` 경로만 설정 가능하게 | 버림 — "원본이 루트에 있으면 대기" 규칙이 그대로라 문제 해결 안 됨 |

화면 표현: 목록형(A) vs 흐름도형(B) 중 **흐름도형** (사용자 선택).

## 설계

### 1. 폴더 역할 (`Dirs` 재정의)

```ts
type Role = "droneRaw" | "gogglesRaw" | "droneMerged" | "gogglesMerged" | "hud" | "logs";
interface Dirs {
  project: FileSystemDirectoryHandle;          // dji_state.json 위치, 새 결과 폴더의 부모
  droneRaw: FileSystemDirectoryHandle;         // 읽기 전용
  gogglesRaw: FileSystemDirectoryHandle | null; // 읽기 전용, 선택
  droneMerged: FileSystemDirectoryHandle;      // 쓰기
  gogglesMerged: FileSystemDirectoryHandle;    // 쓰기
  hud: FileSystemDirectoryHandle;              // 쓰기
  logs: FileSystemDirectoryHandle | null;      // 읽기 전용, 선택
}
```

- 역할별 핸들은 IndexedDB 에 **프로젝트별로** 기억 (키: `project` + 역할 → 핸들). 다음 실행 때 그대로 연다. 권한이 없거나 SD 카드가 빠졌으면 그 칸만 "다시 연결" (지금 고글 폴더와 같은 방식).
- 자동 채움 규칙 (프로젝트 폴더의 바로 아래 폴더 이름, 대소문자 무시, 먼저 맞는 것):
  - 드론 원본: `aircraft_raw`, `drone_raw`, `raw` → 없으면 **프로젝트 폴더 자체** (DJI_*.MP4 가 맨 위에 있는 예전 구조)
  - 고글 원본: `google_raw`, `goggles_raw`, `goggles` → 없으면 비움(선택)
  - 드론 병합본: `aircraft_merged`, `drone_merged`, `2_ready` → 없으면 `aircraft_merged/` 새로 만듦
  - 고글 병합본: `google_merged`, `goggles_merged` → 예전 구조(`2_ready` 있음)면 `2_ready` → 없으면 `google_merged/` 새로 만듦
  - HUD: `hud` → 예전 구조면 `2_ready` → 없으면 `hud/` 새로 만듦
  - 비행기록: `FlightRecords` → 없으면 비움
  - 새 폴더 이름 접두어는 드론 원본 폴더 이름을 따른다 (`aircraft_raw` → `aircraft_merged`, `google_merged`; 그 외 → `drone_merged`, `goggles_merged`). "새로 만듦" 폴더는 **시작을 누를 때** 만든다.
- 예전 구조에서 쓰던 `3_uploaded/`, `_sources/` 는 **읽기용 검색 위치**로만 남긴다 (예전에 옮겨진 파일을 찾기 위해). 새로 옮기지 않는다.
- 예전 `_excluded/` 안의 원본은 **원본 클립으로 다시 읽고** `overrides.excluded = true` 를 자동으로 붙인다 → 제외 화면에서 상태만으로 되돌릴 수 있음. *(구현자 판단)*
- 고글: 고글 원본 역할 = 폴더 하나. 예전에 따로 연결해 둔 고글 폴더(IndexedDB `"goggles"`)가 있으면 그것을 고글 원본으로 옮겨 오고, 프로젝트 안의 예전 `goggles/` 폴더는 **추가 읽기 위치**로 계속 검색. 같은 파일명이 둘 다 있으면 고글 원본 쪽 우선. 링크는 파일명 기준이라 그대로 유효. *(구현자 판단)*

### 2. 완료 판정 (`buildLibrary` 변경)

- 지금: 루트 원본이 있으면 대기, 없고 기록이 있으면 완료.
- 바꾼 뒤: **기록(`state.videos`)의 결과 파일이 결과 폴더(또는 예전 검색 위치)에 실제로 있으면 완료**. 그 기록의 `sources` 에 해당하는 원본 클립은 대기 목록에서 뺀다. 원본이 원본 폴더에 그대로 있어도 상관없다.
- 클립 1개짜리 비행: 병합이 필요 없다. 결과 = 원본 파일 그 자체 (복사·이동 없음). ① 단계에서 "해당 없음"으로 보이고 바로 ② ③ 대상이 된다. 기록은 `{ variant 없음, sources: [원본] }` 으로 남겨 제목·업로드 상태를 담는다.
- 결과 파일이 사라진 기록(예: Avata2 의 옛 단일 클립 7개는 MP4 없이 LRF/SRT 만 남음, HUD 3개는 정리 때 제외됨): 원본 MP4 가 있으면 대기로. 없으면 완료 목록에 **"파일 없음"** 표시로 남긴다 (7개 중 5개는 YouTube 업로드 기록이 있어 숨기면 안 됨). 기록은 지우지 않는다. *(구현자 판단)*
- **기록 없는 병합본 받아들이기**: 드론 병합본 폴더에 `<stem>_merged.MP4` 가 있는데 기록이 없으면 (Avata2 의 `..._0017_D_merged.MP4`), 같은 id(`stem`)로 묶인 대기 비행의 클립 프레임 수 합과 병합본 프레임 수가 같을 때만 그 비행의 결과로 기록을 만든다. 다르면 대기 + "기록 없는 병합본" 경고. 재병합으로 26GB 중복을 만들지 않기 위함. *(구현자 판단)*
- **단계별 상태**: `Flight.status` 하나 대신 단계마다 상태 — `drone: "todo"|"done"|"n/a"`(단일 클립 = n/a), `goggles: "none"|"todo"|"linked"|"done"`, `hud: "off"|"todo"|"done"`. 사이드바 "대기" = 어느 단계든 todo, "완료" = 모든 단계가 done/n/a/off. 단일 클립 비행은 메모리에서 기록을 만들어 바로 ②③·업로드 대상이 되고, 실제 저장은 ③·업로드·제목 수정 등 무언가 기록을 쓸 때. *(구현자 판단)*

### 3. 쓰기 위치 (작업 함수 변경)

| 작업 | 지금 | 바꾼 뒤 |
|---|---|---|
| `doMerge` | `2_ready/` 에 쓰고 원본을 `_sources/` 로 이동, 단일 클립은 원본을 `2_ready/` 로 이동 | `droneMerged/` 에 쓰기만. 원본 이동 없음. 단일 클립은 기록만 남김 |
| `doGogglesMerge` | `2_ready/*_goggles.MP4` | `gogglesMerged/*_goggles.MP4` |
| `doOverlay` | `2_ready/*_hud.MP4(.part)` | `hud/*_hud.MP4(.part)`. 입력 = 병합본 또는 (단일 클립이면) 원본 |
| `addGoggles` (SD 카드에서 복사) | 프로젝트 `goggles/` 로 복사 | 고글 원본 폴더로 복사 (그때만 쓰기 권한 요청). 고글 원본 폴더가 없으면 프로젝트에 `goggles_raw/` 만들고 역할 지정 |
| `tidyExcluded` / `restoreExcluded` | 원본을 `_excluded/` 로 이동/복귀 | **삭제**. 제외는 상태(`overrides`)로만 |
| `.part` 정리 | `2_ready/` | 세 결과 폴더 |
| 텔레메트리 json | 결과 옆 | 그대로 결과 옆 |

### 4. 단계별 일괄 처리

단계마다 대상·실행을 따로 둔다. 기존 `runOne` 을 단계 함수 셋으로 나눈다.

| 단계 | 대상 (todo) | 실행 | 건너뜀 |
|---|---|---|---|
| ① 드론 병합 | 클립 2개 이상 + 병합본 없음 | `doMerge` | — |
| ② 고글 병합 | (a) 고글 후보는 있는데 아직 맞추지 않은 비행 → 자동 맞춤, (b) 연결 2개 이상 + 병합본 없거나 연결이 바뀜 → 병합 | `syncCore` 후 `doGogglesMerge` | 연결 1개 = 병합 불필요("연결됨") |
| ③ HUD | HUD 를 켰고(계기·지도·고글 OSD 중 하나) HUD 영상이 없는 비행 | `doOverlay` | ① 이 필요한데 안 끝난 비행은 "병합 먼저"로 세고 건너뜀 |

- **전부 순서대로**: ① 전체 → ② 전체 → ③ 전체 (단계 단위, 비행 단위 아님). 앞 단계에서 실패한 비행은 뒤 단계에서 건너뛴다.
- 진행 카드(`JobCard`): "② 고글 병합 · 3/7 · 비행 이름 · 42%". 하나 실패해도 다음 비행 계속, 중단하면 거기서 멈춤 (지금 규칙 유지).
- 비행 하나의 프로젝트 화면 버튼(병합 / HUD 만들기)은 지금처럼 유지하되 같은 단계 함수를 쓴다.
- 기존 "모두 처리" 버튼은 단계 줄로 대체.
- **폴더를 열 때 고글 자동 맞춤은 하지 않는다** (사용자 결정). 지금 `app.tsx` 의 "열면 모든 비행 자동 맞춤" 효과를 없애고, 맞춤은 ② 단계(또는 비행 화면의 고글 탭에서 비행 하나)에서만. 폴더를 열면 화면이 바로 뜬다.

### 5. 화면

**첫 화면 (흐름도형)** — 프로젝트 폴더 칸이 위에, 그 아래 흐름도:

```
[📁 프로젝트 폴더  ~/Desktop/Avata2            바꾸기]
  원본(읽기 전용)          병합                    합성
  [🛸 드론 원본 101] →  [① 드론 병합본 13 찾음] ↘
                                                 [③ HUD  새로 만듦]
  [🥽 고글 원본 26 ] →  [② 고글 병합본 새로 만듦] ↗
  [📜 비행기록 (선택)  없음                      고르기]
                                          [시작]
```

- 칸 상태 표시: 찾음 / 새로 만듦 / 읽기 전용 / 다시 연결 / 비움(선택). 칸마다 바꾸기, 선택 칸은 "없음" 가능.
- 드론 원본에 DJI 파일이 0개면 경고(칸 빨강), 시작은 가능.
- 사이드바 아래 `FolderStatus` 도 같은 역할 목록(작게)으로 바꾸고, 누르면 첫 화면 흐름도를 다시 연다 ("폴더 바꾸기").

**라이브러리 단계 줄** — 목록 위:

```
① 드론 병합 3 [실행] → ② 고글 4 [실행] → ③ HUD 9 [실행]      [전부 순서대로]
```

대상 0개인 단계는 체크 표시 + 버튼 비활성. 작업 중엔 모든 실행 버튼 비활성.

### 6. 지도 오류 표시

- `TileSource` 세션 실패(403 등)를 삼키지 않고 상태로 들고 있는다 (`error: string | null`).
- 플레이어/HUD 탭: 미니맵 자리에 "지도를 불러오지 못했습니다 (403) — 키의 웹사이트 제한에 이 주소를 추가하세요: <origin>" 한 줄. 렌더 시에는 알림(toast) 한 번, 궤적만으로 계속.

### 7. 기존 데이터 이전

- 상태 파일 형식은 그대로 (`version: 1`). 키는 파일명이라 폴더가 바뀌어도 유효.
- Avata2: 프로젝트 폴더 `Avata2` → 자동 채움으로 `aircraft_raw`·`google_raw`·`aircraft_merged` 를 찾고 `google_merged`·`hud` 를 새로 만듦. 병합 기록 7개(`*_merged.MP4`)는 완료, 그 원본 클립은 대기에서 빠짐.
- 예전 구조: 프로젝트 = 드론 원본 = 루트, 결과 3종 = `2_ready`, 검색 위치에 `_sources`·`3_uploaded`·`_excluded`. 원본은 더 이상 옮기지 않음.

## 사용자가 정한 것

- 아카이브 구조를 앱에 맞추지 않고 앱이 역할별 폴더를 지원 (B)
- 첫 화면에서 폴더를 각각 시각적으로 지정, 흐름도형
- 단계: 드론 병합 / 고글 병합 / HUD 각각 일괄
- 고글 자동 맞춤은 폴더 열 때가 아니라 ② 단계에서만

## 구현자가 정할 것 (제안한 기본값)
