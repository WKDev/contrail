# 기체 여러 대 + 공용 고글 설계

작성: 2026-11-23 · 상태: 승인됨 (사용자: "1,2,3 모두 해라") · 이전 설계: `2026-11-23-folder-roles-and-step-batch-design.md` (역할별 폴더·단계별 일괄, 구현·병합 완료)

## 왜

- 사용자는 Avata 2 외에 O4 Air Unit 을 쓰는 다른 기체(Pavo Pro 2)도 날린다. 두 기체 영상을 **한 라이브러리에서 같이** 보고 관리하고 싶다.
- 고글은 하나를 여러 기체에 같이 쓴다. 고글 녹화가 어느 기체 비행인지 앱이 가려내야 한다.
- O4 같은 별도 에어 유닛은 시계·녹화 시작/정지·화면이 Avata 2 처럼 고글과 딱 맞지 않을 수 있다 → 시간만으로 맞추는 지금 방식이 깨질 수 있다.

## 확인한 사실

- 드론 영상(`aircraft_raw/*.MP4`)에는 기체 정보 문자열이 있다: `DJI Avata2`, `FC8485`, `dvtm_AVATA2.proto`.
- 고글 녹화(`google_raw/DJI_0045.MOV`) 앞 2MB·뒤 4MB 에서는 연결된 기체 정보를 찾지 못했다 → 고글 쪽은 시간·화면 내용으로 주인을 찾아야 한다.
- 지금 원본 인식은 파일명 `DJI_YYYYMMDDhhmmss_NNNN_D.MP4` 에 의존(`RAW_RE`, `parseStart`). O4 기체(Pavo Pro 2) 실물도 같은 형식(`DJI_20261115123631_0001_D.MP4`), 모델 문자열 `DJI O4P`/`FC8885`, `dvtm_O4P.proto`.
- O4 `.SRT` 에는 노출값·시각만 있고 GPS·자세·고도 없음 → 이 기체는 HUD 계기·지도에 쓸 비행 데이터가 없다고 보고 처리.
- 실제 고글 녹화 하나(`DJI_0122.MOV` 등)가 같은 기체의 비행 여러 개에 시간대별로 연결돼 있다 (11-15, 장면 점수로 나뉜 비행 3개).
- `Avata2/aircraft_raw/` 안에 오늘 생긴 두 번째 상태 파일(11월 고글 연결 31개, 새 점수 8개, 오늘 고친 레이아웃)과 빈 예전 구조 폴더 5개가 있다. `Avata2/pavopro2/` 에 원본이 `raw/` 없이 바로 있다 (`_0002` 는 LRF 만).

## 목표

1. 프로젝트 폴더 아래 **기체별 하위 폴더**: `<기체>/raw`, `<기체>/merged`, `<기체>/hud`. 고글은 공용 `goggles_raw/`, `goggles_merged/`.
2. 라이브러리는 모든 기체 비행을 한 목록에 날짜순으로, 카드에 기체 이름, 사이드바에 기체별 필터.
3. 비행 묶기(①)는 **기체별로** — 다른 기체 클립끼리는 이어 붙이지 않는다.
4. 고글 녹화는 **한 기체에만** 배정(배타)하고, 그 기체의 여러 비행에 시간대별로 연결될 수 있다 (실제 데이터). 기체 판정 순서: 시간 겹침 → (애매하면) 화면 내용 점수 → (그래도 비슷하면) 사용자 선택. 저장된 연결은 수동처럼 유지.
8. 비행 데이터가 없는 기체(O4)는 HUD 계기·지도를 기본으로 끄고 ③ 은 고글 OSD 만 합성 (사용자 결정 A).
9. HUD·OSD 배치는 **기체별** (사용자 결정). 새 기체는 기본값에서 시작, 기존 프로젝트 배치는 Avata 2 로.
5. 기체별 **시계 오차 학습**: 확실히 맞춘 비행에서 "기체 시각 − 고글 시각" 을 구해 같은 날 그 기체의 다른 파일 후보 찾기에 쓴다.
6. 기체 표시 이름은 폴더 이름(`avata2`), 기체 모델은 영상 안 정보로 자동 판별해 보조로 보여 줌(`DJI Avata2`).
7. 바탕화면 `Avata2` 폴더를 새 구조로 이전 (같은 디스크라 즉시, 원본 내용 변경 없음).

## 비목표

- Betaflight 블랙박스 로그로 HUD 계기 만들기 (별도 작업).
- 고글 녹화의 OSD 모양으로 기체 계열 구분 (O4 실물 샘플 확보 후 별도 작업).
- 여러 프로젝트 동시 열기.

## 실패로 보는 것

- 고글 녹화 하나가 두 기체 비행에 동시에 붙음.
- Avata 2 와 Pavo Pro 2 클립이 시간상 가깝다고 한 비행으로 묶임.
- 이전 후 Avata 2 의 기존 결과(병합본 7개, 고글 연결, 레이아웃, 수동 선택)가 사라지거나 다시 병합 대상이 됨.
- 원본 파일이 옮겨지거나 지워짐 (이전 설계의 불변 조건 유지 — 단 7번 이전 작업은 사용자가 승인한 1회성 폴더 재배치).

## 접근 방법 (검토한 것)

| 안 | 내용 | 결과 |
|---|---|---|
| 기체마다 프로젝트 따로 | 코드 변경 없음 | 버림 — 한 라이브러리에서 같이 보고 싶음 |
| A. 맨 위에 `<기체>_raw/_merged/_hud` | 지금 구조 확장 | 버림 — 기체 수 × 3 폴더가 맨 위에 쌓임 |
| **B. 기체별 하위 폴더 + 공용 고글** | `avata2/{raw,merged,hud}`, `goggles_raw/` | **채택** (사용자 선택) |
| C. 원본만 기체별, 결과 공용 | 폴더 최소 | 버림 — 탐색기에서 기체별로 안 나뉨 |

## 설계

### 1. 폴더 구조와 인식

```
DroneArchive/            ← 프로젝트 폴더 (dji_state.json)
├── avata2/
│   ├── raw/             드론 원본 (읽기만)
│   ├── merged/          ① 병합본
│   └── hud/             ③ HUD
├── pavopro2/
│   ├── raw/ merged/ hud/
├── goggles_raw/         공용 고글 원본 (읽기만, "고글 영상 추가" 때만 씀)
├── goggles_merged/      ② 고글 병합본
└── FlightRecords/       (선택)
```

- 기체 폴더 = 프로젝트 바로 아래에서 `raw/` 하위 폴더를 가진 폴더. 이름이 기체 id·표시 이름.
- 기체 폴더 안 `merged/`, `hud/` 가 없으면 시작할 때 만든다.
- 기체 폴더가 하나도 없으면 **지금 방식 그대로**(단일 기체: `aircraft_raw`/예전 `2_ready` 구조 추정). 즉 이전 설계의 `detectRoles` 는 "기체 하나" 경우로 남는다. 이때 기체 id 는 `default`.
- 설정 화면에서 기체별 칸을 바꿀 수 있는 것은 지금과 같다 (기체마다 raw/merged/hud 세 칸).

### 2. 데이터 모델

- `Dirs` → `{ project, aircraft: AircraftDirs[], gogglesRaw, gogglesExtra, gogglesMerged, logs, legacy, excluded }`, `AircraftDirs = { id, raw, merged, hud }`.
- `Index.files` 의 `FileRef` 에 `aircraft: string` 추가. 같은 파일명이 두 기체에 있으면 키를 `<aircraft>/<name>` 으로 구분 (기본 키는 지금처럼 파일명, 충돌할 때만 접두).
- `Flight.aircraft: string`. `Flight.id` 는 지금처럼 첫 클립 stem (기체 간 stem 충돌 시 `<aircraft>/<stem>`).
- 상태 파일: `version: 1` 유지. 기존 기록에는 기체 정보가 없으므로 **없으면 파일이 발견된 기체**로 본다. 새로 쓰는 `VideoRecord` 에 `aircraft?: string` 추가.
- 기체 모델: 기체 폴더의 첫 원본 MP4 앞부분에서 `DJI <모델>` 문자열을 찾아 캐시 (`AircraftInfo.model?: string`). 못 찾으면 비움.

### 3. 원본 인식 (O4 대비)

- 기체 `raw/` 안에서는 파일명이 `RAW_RE` 와 맞지 않아도 `.MP4` 면 원본 후보로 받는다. 시작 시각 = 파일명 시각, 없으면 `mvhd` 생성 시각, 그것도 없으면 파일 수정 시각 − 길이.
- `stem` = 확장자 뺀 파일명. LRF/SRT 짝은 같은 stem 이 있을 때만.

### 4. 비행 묶기 (①)

- `decide`/`groupClips` 를 **기체별로 따로** 호출하고 결과를 합친다. 연속성 점수 키(`pairKey`)는 기체가 다르면 만들지 않는다.
- ① 단계 대상·실행은 기체 상관없이 시간순 (지금과 같음), 결과는 그 기체의 `merged/`.

### 5. 고글 배정 (②) — 공용 고글

새 순수 함수 `ownerOfGoggles(goggles, flights, links, clockErr, manualOwner) → Map<gogglesFile, { aircraft?: string; by: "linked" | "manual" | "time" | "ambiguous" | "none"; candidates: string[] }>` — 고글 녹화의 **주인 기체**를 정한다.

0. 이미 연결된 녹화는 연결된 비행의 기체가 주인(`linked`), 사용자가 기체를 고른 녹화는 그 기체(`manual`).
1. 아니면 기체별로 그 기체 비행들과의 시간 겹침 합을 구해(기체 시계 오차 보정) 가장 큰 기체가 주인(`time`).
2. 2등 기체 겹침이 1등의 80% 이상이면 `ambiguous` → ② 단계에서 후보 기체마다 가장 많이 겹치는 비행과 `syncGoggles` 를 돌려 점수가 높은 쪽(차 ≥ 0.1)을 주인으로 저장, 아니면 사용자 선택 대기.
- 비행별 후보(`gogglesOf(f).candidates`)는 주인이 그 비행의 기체인 녹화 중에서 지금처럼 클립별 시간 겹침으로 찾는다 → 한 녹화가 같은 기체의 여러 비행에 시간대별로 붙는 것은 그대로 허용.
3. 시간 겹침 후보가 하나도 없으면(시계가 크게 틀림): 그 날 같은 기체에 학습된 오차가 있으면 적용해 다시 1번. 없으면 "시각 없이 맞추기" 후보로 표시만 하고 자동 배정 안 함 (사용자가 비행을 고르면 그 비행과 넓은 범위(±10분)로 `syncGoggles`).
4. 사용자가 고른 연결(`manual`)은 항상 우선, 다른 비행에서 그 고글 녹화를 뺀다.
- 지금 `gogglesOf(f).candidates`(비행 → 겹치는 고글)는 이 배정 결과에서 그 비행에 배정된 것만 돌려주도록 바꾼다 → 한 녹화가 두 비행 후보로 동시에 뜨지 않는다.

### 6. 기체별 시계 오차 학습

- 상태에 `clock?: Record<aircraftId, { offset: number; day: string; from: string }[]>` (offset = 기체 시각 − 고글 시각, 초).
- `syncGoggles` 결과 점수 ≥ 0.6 이면 `offset = (flight.start + result.offset 보정) 기준 차이` 를 그 기체·그 날에 기록 (같은 날 여러 개면 중앙값).
- Avata 2 처럼 오차가 작은 기체(|offset| < 3초)는 기록만 하고 판정에 영향 없음.
- 설정 화면 기체 칸에 "시계 오차 +N초 (날짜)" 표시, 지우기 버튼.

### 6-1. 기체별 기본값·배치

- 기체 비행 데이터 유무: 기체의 첫 원본 클립에서 `readTelemetry` 결과에 유효한 GPS 또는 자세가 있으면 있음. 없으면 그 기체 비행의 prefs 기본값은 계기·지도 끔 (사용자가 켠 값은 존중).
- 상태에 `layouts?: Record<aircraftId, Layout>`. `layoutOf(s, aircraft)` = 기본값 + (`layouts[aircraft]` ?? 예전 `layout`). HUD 탭·고글 탭 편집은 열린 비행의 기체 배치를 바꾼다.

### 7. 화면

- **설정 흐름도**: 기체마다 한 줄 `[🛸 avata2 원본] → [① 병합본] → [③ HUD]`, 맨 아래 공용 줄 `[🥽 고글 원본] → [② 고글 병합본]` 이 각 기체의 ③ 으로 화살표. "기체 추가" 버튼 = 프로젝트에 `<이름>/raw` 만들기 또는 기존 폴더 고르기.
- **사이드바**: 기체 목록(이름 · 모델 · 비행 수)을 필터로. 폴더 상태 목록은 기체별로 접기.
- **비행 카드**: 기체 이름 칩.
- **고글 화면/고글 탭**: 배정 방식 표시(시간/화면/수동), `ambiguous` 면 후보 비행 선택 버튼.

### 8. 기존 데이터 이전 (1회, 사용자 승인)

- 상태 파일 합치기: 루트 `dji_state.json`(영상 기록 26개·prefs·remote·고글 연결 23개) + `aircraft_raw/dji_state.json`(고글 연결 31개·점수·오늘 레이아웃). 키가 겹치지 않는 항목은 합치고, 레이아웃은 안쪽(최신) 것을 `layouts.avata2` 로. 안쪽 파일은 지우지 않고 루트에 `dji_state.aircraft_raw-backup.json` 으로 보관.
- `aircraft_raw` 안 빈 예전 구조 폴더 5개(`2_ready`, `3_uploaded`, `_sources`, `_excluded`, `goggles`)는 비어 있을 때만 `rmdir`.
- 바탕화면 `Avata2` → `DroneArchive` 로 이름 변경 (사용자 승인된 B 구조).
- `aircraft_raw` → `avata2/raw`, `aircraft_merged` → `avata2/merged`, `google_raw` → `goggles_raw`, `pavopro2/DJI_*` → `pavopro2/raw/`, `dji_state.json` 그대로 루트.
- 같은 디스크 `mv` (즉시, 파일 내용 불변). 이전 전후 파일 수·총 크기 비교로 확인.
- 브라우저에 기억된 프로젝트 핸들은 이름 변경 후 무효가 될 수 있음 → 첫 화면에서 `DroneArchive` 를 다시 고르면 됨.

## 사용자가 정한 것

- 한 라이브러리에서 여러 기체를 같이 관리
- 구조 B: 기체별 하위 폴더 + 공용 고글 폴더
- 고글은 공용 하나, 기체 판정은 앱이 시간 → 화면 내용 → 수동 순서로

## 구현자가 정할 것 (제안한 기본값)

- 기체 폴더 인식 규칙(`raw/` 를 가진 하위 폴더), 기체 없으면 단일 기체 호환 모드
- 파일명 충돌 시에만 `<aircraft>/` 접두
- ambiguous 기준(겹침 80%, 점수 차 0.1), 시계 오차 기록 기준(점수 ≥ 0.6), 영향 없음 기준(3초)
- 이름 변경 대상 `DroneArchive`
- 테스트: 기체 폴더 인식, 기체별 묶기(가까운 시각의 두 기체 클립이 분리되는지), `assignGoggles`(배타·ambiguous·시계 오차 적용·manual 우선), 원본 시각 대체 규칙
